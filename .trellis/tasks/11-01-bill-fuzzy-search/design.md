# 账单搜索设计

## 边界与数据流

Android 搜索框 → 不可变查询对象（关键词、全部历史/所选月、账户、类型）→ 鉴权交易列表及日汇总 → SQLite 字面条件 → 分页完整读取、代次隔离与展示。搜索只读，数据库 schema 和账务计算不变。

新增独立搜索参数，不改变既有 `q` 备注搜索；新参数对备注、实际分类名称、账户名称、标签和按整数分精确生成的两位小数元字符串做 OR 包含匹配，其他过滤条件使用 AND。对 SQL 特殊字符做字面转义并参数化。历史软删分类/账户名称可查询，其交易仍须活跃。分页、total 与日汇总共享同一条件。金额以整数运算生成展示字符串，不用浮点换算；定义 Unicode 与大小写行为并测试。

服务端返回搜索协议标记 `searchVersion: 1` 和 `searchRevision`（64 位 SHA-256），对匹配结果的稳定排序、交易行及退款摘要取指纹；列表计数、指纹、页和退款信息在同一 SQLite 读事务中，月汇总在同口径读事务中生成相同指纹。Android 对每页及月汇总校验标记和指纹：跨页变化拒绝完整结果，月汇总变化清除过期列表并提示刷新；旧服务器忽略未知参数时显示服务不支持，而非把未筛选数据当搜索结果。未经搜索的旧协议保持兼容。

为限制逐页完整指纹扫描的同步成本，服务端在指纹计算前对非空搜索进行同事务预检：匹配结果最多 10,000 笔且可变文本字段总 UTF-8 大小最多 16 MiB，超过任何上限返回可操作的中文错误，不返回部分结果；普通非搜索月视图保持原有边界。

## 搜索范围与展示

默认非空搜索跨历史，不传 from/to；可切换所选月，空搜索回原月视图。继续支持账户、类型与当前月选择，查询变化后清除旧结果并使用代次守卫。月范围调用原日汇总并核验；跨历史不调用不超过32天的汇总接口，按日期分组，不显示不可信汇总。沿用当前完整分页与安全上限，超限或并发变化显式报错而非截断；如规模不允许可讨论独立分页 UI，不默默扩大范围。

## 变更边界

- `packages/server/src/routes/transactions.ts`、`services/transaction-types.ts`、`transaction-service.ts`：新搜索协议、统一谓词和兼容性标志。
- `packages/server/test/transactions.test.ts` 等：真实路由、特殊字符、金额、旧 q、分页、汇总与认证覆盖。
- Android `TransactionsTab.kt`、`TransactionQueryHelper.kt`、列表加载器和必要 repository：入口、范围、状态隔离和能力校验。
- Android 对应 JVM 测试及 `clients/android/README.md`：行为回归和功能目录。
- 不更改 ledger 写入逻辑、统计定义或现有生产部署；不覆盖未提交内容。

## 风险和回退

部署新版服务端后再发布依赖该接口的 APK；客户端对旧服务端明确降级提示。源码回退时恢复对应新参数代码即可，因无 schema 改动无需迁移；生产部署或安装需另行授权。历史搜索存在范围及结果数量限制，错误状态必须诚实。实际设备交互与本地测试分别记录。
