# 实施计划

> 仅在用户审阅最终摘要并明确批准后启动任务和修改产品代码。

1. 阅读相关 Trellis 规范、Android 账单目录和现有工作区差异；保留所有既有更改。
2. 定义兼容旧 `q` 的独立只读搜索契约；实现字面匹配、整数金额格式、跨月分页和能力标记。
3. 服务端添加隔离数据库路由测试：文本、数字、特殊字符、历史账户/分类、组合筛选、分页 total、月汇总、权限及老参数。
4. Android 增加搜索入口、全历史/所选月范围、清除与空态；跨历史不调用月汇总，月范围继续校验汇总，防止旧请求回写。
5. 检查旧后端能力标记缺失时明确提示；添加 Android 查询/解析/代次等 JVM 回归。
6. 更新 Android README 受影响 stable ID、API、入口、限制、变更日志，区分源码测试与真机。
7. 运行 server 相关测试及 typecheck/lint、Android `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug`；检查最终 diff 和现有脏文件。
8. 报告验证结果和缺口；生产部署、安装和设备财务操作需单独确认。
