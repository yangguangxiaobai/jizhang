# T7 基础数据管理页(分类/账户/标签)

> 父任务:`.trellis/tasks/09-11-web-pwa`
> 依赖:**T4**(账单已可用,需引用分类与账户)。T4 之后可并行于 T8/T9。

## Goal

提供分类、账户、标签的管理界面与接口,让用户能自定义记账的基础字典,并保护内建项不被误删。

用户价值:预置分类不可能覆盖所有人的生活方式;不能自定义就等于被迫用别人的分类体系。

## Background

- 字段定义见父任务 `design.md` §3;权威来源是参考项目 `app_database.dart:13-41`
- 分类:`type` 0=支出 1=收入,含 `icon` 与 `color`
- 账户 `type` 枚举:0=现金 1=储蓄卡 2=信用卡 3=支付宝 4=微信 5=其他
- **标签没有独立表** —— 标签"名字即身份",存于 `transactions.tags_json`
  (父任务 design.md §3 的取舍)。所以"标签管理"是**派生视图**,不是独立实体

## Requirements

### R1 分类接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/v1/categories` | 列表,支持 `?type=0\|1` 过滤 |
| POST | `/api/v1/categories` | 新建 |
| PATCH | `/api/v1/categories/:id` | 编辑名称/图标/颜色/排序 |
| DELETE | `/api/v1/categories/:id` | 软删除 |

### R2 账户接口

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/v1/accounts` | 列表(含 `initialBalanceCents`) |
| POST | `/api/v1/accounts` | 新建 |
| PATCH | `/api/v1/accounts/:id` | 编辑 |
| DELETE | `/api/v1/accounts/:id` | 软删除 |

### R3 内建项保护

- `isBuiltin = 1` 的分类与账户**不允许删除** → 403(与参考项目 `app_database.dart:19` 的保护标记一致)
- 允许编辑内建项的名称/图标/颜色(参考项目允许编辑预置模板)
- 删除分类/账户时,若有账单引用它 → **需定案并测试**:
  建议行为 = 允许软删,已存在的账单仍能显示历史名称(不级联改账单,
  因为改账单会篡改历史记录),但该分类不再出现在新建账单的可选列表里

### R4 标签管理(派生视图)

- `GET /api/v1/tags` → 返回标签名 + 使用次数(统计 `transactions.tags_json`)
- 重命名标签:重写所有引用该标签的账单的 `tags_json`(名字即身份,改名字等于改所有引用)
- 删除标签:从所有账单的 `tags_json` 中移除该名字
- 两个操作都必须在**单事务**内完成,且合并后仍保持去重保序(复用 T4 的标签解析规则)
- ⚠️ 参考项目记录了"重命名/删除通过重写账单传播"的设计(`app_database.dart:97` 注释)

### R5 排序

- 分类与账户支持 `sort_order`;界面上提供排序调整(至少支持上移/下移)
- 列表查询按 `sort_order` 升序,其次按创建顺序

### R6 界面

- 分类管理页:按支出/收入分组展示,显示图标与颜色;可新增/编辑/删除;内建项删除按钮置灰
- 账户管理页:展示名称、类型、初始余额;可新增/编辑/删除
- 标签管理页:展示标签名与使用次数;可重命名/删除
- 移动优先:列表项点击目标 ≥44px,编辑用底部抽屉或独立页面,不用难点的行内菜单

### R7 图标与颜色

- `icon` 为字符串,`color` 为整数(参考项目用整数存颜色值)
- ⚠️ **需查证**:参考项目 `seed_service.dart` 里 `icon` 存的是 Material 图标名还是自定义标识。
  Web 端需选定图标方案(如 iconify 的图标名集合),并做一次映射。
  若直接沿用 Material 名,Web 端可用 `@iconify-json/mdi` 之类对应集合

## Acceptance Criteria

- [ ] AC1 新增一个支出分类后,记账页面的分类选择器里能看到它
- [ ] AC2 删除内建分类返回 403,且该分类仍可用
- [ ] AC3 编辑内建分类的名称后,列表与记账页显示新名称
- [ ] AC4 软删除一个被账单引用的分类后,历史账单仍能正确显示该分类名称,新账单不能再选它
- [ ] AC5 `GET /api/v1/tags` 返回的标签与使用次数与账单数据一致
- [ ] AC6 重命名标签后,所有原引用该标签的账单都显示新名字
- [ ] AC7 删除标签后,该标签不再出现在任何账单上,其他标签不受影响
- [ ] AC8 标签重命名/删除在事务内完成:人为制造中途失败不产生半更新的账单
- [ ] AC9 分类与账户的排序调整持久化,刷新后顺序不变
- [ ] AC10 账户可记录初始余额,并在列表正确显示(元/分转换正确)
- [ ] AC11 `pnpm --filter server test` 全绿

## Out of Scope

- 月度/年度统计 → T8
- 分类的合并去重(参考项目有 `seed_dedup_test` / `template_dedup_test`)→ 本期不做
- 多账户的借贷/信用卡账单周期计算 → 父任务 MVP 范围外
- 分类预算的独立设置(预算通过模板设置)→ 不做

## Technical Notes

- 标签没有独立表,所以"标签管理"只能派生。若将来需要标签备注/颜色/排序,
  才考虑建 `tags` 表;本期不建,避免与"名字即身份"语义冲突
- 重写 `tags_json` 时要复用 T4 实现的解析与序列化函数,不要另写一套
  (否则去重保序规则会在两处漂移)
- 参考项目 `category_management_page.dart`(18.6KB)与 `account_management_page.dart`(18.7KB)
  可参考交互,但不要照搬其全部功能
