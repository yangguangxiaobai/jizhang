# 动画十二原则与动效系统 — 需求

> 父任务 `09-11-roadmap-2`。第二阶段之后的体验层工作。
> 规范落在 `.trellis/spec/frontend/motion-guidelines.md`。

## Goal

界面此前**完全是静止的**:全仓只有一个 `transition: width 0.2s ease`(预算进度条),按钮没有按压反馈,
换页是硬切,列表一次性出现,错误没有任何强调。

本任务用**动画十二原则**建立一套可维护、可验证的动效系统。重点不是"加动画",而是:

1. **让动效成为设计语言**,而不是零散的装饰 —— 每个动作都能对应到一条原则;
2. **让"不加动画"也成为设计决定** —— 明确写下拒绝哪些动画以及原因;
3. **让动效可被验证** —— 静态审计 + 真实浏览器测量,而不是"看起来还行"。

## Background

### 为什么这件事值得单独做

动效是唯一**无法通过阅读代码评审**的 UI 部分。一屏 `transition: 0.3s ease` 无论产生的是考究的
界面还是躁动的界面,源码看起来都一样。因此本任务的所有规则都写成**可检查**的形式:
9 条由 `scripts/check-motion.mjs` 静态强制,其余由 `scripts/render-motion.mjs` 在真实浏览器里测量。

### 既有硬约束(必须遵守)

- 目标设备是 **iPhone**;所有可点元素 ≥ 44px,输入 ≥ 16px 字号(见 `component-guidelines.md`);
- 客户端**只渲染不计算**;金额、周期、结余池全部来自服务端;
- 不引入依赖(图表是手写 SVG,bundle ~42 kB gzip);
- 颜色只走语义变量;深色模式三态;
- **每个视图的 template 都是 fragment(多根)**,没有单一根元素。

## Requirements

### R1 令牌层

- 时长梯度按**距离**而非重要性分级:`--dur-press` 90ms / `--dur-quick` 140ms /
  `--dur-base` 220ms / `--dur-slow` 320ms;`--stagger` 36ms;`--rise-distance` 8px;
  `--press-scale` 0.97。
- 三条缓动令牌:`--ease-out`(进入)/ `--ease-in-out` / `--ease-pop`(仅小元素、允许过冲)。
  **不设 `--ease-in`**:离场动画被明确拒绝,一条"给离场用"的曲线没有使用者。
- 高度两级 `--lift-1..2`,每级**两个阴影**(紧的关键影 + 宽的环绕影);深色模式整梯加深。
  **不设按压缩放那一级**(按压由挤压表达,且手指压着的阴影本来就看不见),
  **不设 `--lift-3`**(没有东西浮在页面上)。
- 全仓**不得出现字面量时长**;`linear` 不得出现。
- **每条令牌都必须被引用** —— 与"未使用的关键帧"同一条标准,由静态审计强制。

### R2 结构不变式

- **关键帧只写 `from`**:缺省的 100% 帧由元素自身计算样式补齐,因此"基础规则写
  `opacity: 0`、靠动画显示"这类会让元素永久隐形的写法在结构上不可能出现。
- 填充模式一律 `backwards`,不用 `both`(后者会永久占着一个合成层)。
- **只动 `opacity` 与 `transform`**,不动布局属性。
- 所有索引驱动的错峰延迟必须被 `min()` 截断在 6 步以内。

### R3 减少动效契约

- `prefers-reduced-motion: reduce` 下,把全部 `--dur-*` 覆盖为 1ms、`--stagger` 为 0。
- 因为所有时长都是令牌,**整个应用只靠这一个块关闭动效**,任何组件都不需要知道这件事。
- 不采用 `* { animation: none !important }`(会把依赖关键帧呈现状态的元素弄坏,且 `!important`
  让由此产生的 bug 极难从样式表看出来)。
- 保留按压缩放:它是瞬时状态变化,不含位移。

### R4 页面到达(Staging)

- `AppShell.vue` 把出口包在按路由 path 加 key 的 `div.view-slot` 里;
- `main.css` 对 `.view-slot > *` 按 `:nth-child` 施加 0/36/72/… 的错峰到达延迟;
- **于是每个页面无需写任何动效代码就获得分阶段到达**;
- 不使用 `<Transition>` 包 `<RouterView>`:每个视图都是 fragment,包了会静默失效;
- key 是承重的:它让每次导航都产生新元素(动画必然重放),并避免同一视图的
  `/transactions/new → /transactions/:id/edit` 复用 DOM 而残留上一个表单的值。

### R5 十二原则的落地

| # | 原则 | 落地 |
|---|---|---|
| 1 | 挤压与伸展 | 控件按下 `scale(0.97)` |
| 2 | 预备动作 | 按压下沉即蓄力;指示条先行、文字滞后 |
| 3 | 布局/舞台 | 一次只动一件事;离场是硬切 |
| 4 | 关键帧 | 命名姿态的闭集,无内联临时关键帧 |
| 5 | 跟随与重叠 | 错峰到达;标签、图例、坐标轴在其注解对象之后落定 |
| 6 | 缓入缓出 | 三条缓动令牌;禁用 `linear` |
| 7 | 弧线 | 环形图每块绕圆心旋入,按角度顺序形成扫过 |
| 8 | 次要动作 | 活动标签的下划线指示条 + 字形抬升 |
| 9 | 时间节奏 | 时长跟距离走,且总时长有上限 |
| 10 | 夸张 | **只给两处**:错误抖动、唯一"请你处理"卡片的过冲 |
| 11 | 立体感 | 高度两级(关键影 + 环绕影);按下 = 用挤压表达,不加阴影 |
| 12 | 吸引力 | 一套人格:两条曲线、一个距离、一个错峰步长 |

### R6 明确拒绝(与实现同等重要)

- **金额不做数字滚动**:既会显示服务端从未算出的数值,也让用户专门来看的那个数字在一段时间内不可读。
  环形图中心的值改为在弧线到位后以透明度/缩放落定 —— 有表现力,但任何一帧都不显示假数字。
- **不做循环装饰**(shimmer / pulse / 漂浮插图):账本在没有事情发生时就该是静止的,也省电。
- **不做过场离场动画**。
- **不给主题切换加过渡**:明暗切换是一次属性翻转、整页重绘;要做得对就得给每个卡片、边框、文字
  和图表描边都加 `background-color`/`color` 过渡,代价远大于收益;而只给页面背景加过渡比不加更糟
  —— 背景在缓动而卡片在跳变。
- **不用 `linear`**。
- **不给路线根节点加 transition**。

### R7 进度条改用 `transform`

- 两处进度条由 `width: n%` 改为满宽轨道 + `transform: scaleX(var(--fill))`(轨道裁剪);
  模板传单位区间而非百分比字符串。
- 两条进度条在到达时从 0 生长(`fill-grow`),让长度读起来是"量出来的"。

### R8 验证

- `check-motion.mjs` 进 `pnpm build`:审查 `all`、`linear`、字面量时长、`to` 帧、
  布局属性、关键帧定义/引用、动效令牌引用、减少动效覆盖、错峰截断。
- `check-mobile.mjs` 需放行**伪元素**:活动标签下划线是 2px 的装饰(`.tab::after`),
  没有任何手指会落在它上面;把它按"控件高度不足 44px"报错,等于让装饰的尺寸受控件尺寸约束。
- `render-motion.mjs`:测量到达顺序与上限、引擎真实构建的属性、按压反馈
  (`CSS.forcePseudoState`)、指示条绘制态、高度阶梯(明暗两套主题)、环形弧度与柱状生长、
  **以及完整跑一遍减少动效路径**。
- 减少动效下:渲染文本必须与正常模式**逐字相同**,且不得有布局存在但完全透明的元素;
  测量必须在到达结束后进行(错峰期间透明是**预期**行为)。
- 套件签名必须与同族一致:`<out.png> [base-url]`。本套件最初写成了 `[base-url]`,
  于是统一运行的脚本把截图路径当成 base URL 传进来,产生裸的 `TypeError: fetch failed`。
  现在与其余五个一致,并对非 `http(s)` 的 base URL 直接报错说明用法。
- 套件在播种前必须**等待服务端就绪**:它不能假设上游已起。

## Out of scope

- 不引入动画库(Framer Motion / GSAP / auto-animate);
- 不改动任何会计逻辑、接口或数据库;
- 不为动效新增依赖或资源文件。
