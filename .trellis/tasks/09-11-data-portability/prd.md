# 数据导出与导入 — 需求

> 父任务:`09-11-roadmap-2`,对应 R12。第二阶段「块四」。依赖 T13(导出需覆盖周期账单生成的账单,已满足)。

## Goal

给数据一个**出口**和**入口**:导出成 Excel 能直接打开的 CSV,能把导出的文件灌回来,并且能在界面里看到自己的备份。

用户价值:目前唯一的出口是 `cli.js backup`(整库二进制快照)。这意味着**想用 Excel 核账不行、想换设备不行、想知道"我到底备份了没有"也不行**。一份只有自己能看的财务记录,没有可读的出口是真实风险。

## Background

### 仓库现状(已核对)

| 能力 | 现状 | 证据 |
|---|---|---|
| 整库备份 | ✅ 已有,**仅命令行** | `cli-db.ts:114` `createBackup(dbFile, targetDir, retainDays=30)`;`cli.ts:27` `backup <dir> [retain-days]` |
| 备份校验 | ✅ 已有 | `cli-db.ts:46` `verifyBackup(file)` |
| 备份恢复 | ✅ 已有,**必须停服** | `cli-db.ts:185` `restoreBackup(file, dbFile)` 会拒绝在服务运行时恢复 |
| 保留期清理 | ✅ 已有 | `cli-db.ts:151-152` 按 `retainDays` 删除旧归档 |
| CSV 导出/导入 | ❌ **完全没有** | 全仓无 CSV 相关代码 |
| 界面入口 | ❌ 没有 | 前端无任何备份/导出页面 |
| 导出依赖 | 无 CSV 库 | 项目明确"依赖必须自己挣得体积"(`spec/frontend/index.md:17-18`),两个图表都是手写 SVG |

**结论:备份能力强,但被锁在命令行里;导出/导入完全不存在。**

### 必须遵守的既有硬约定

- **金额整数分、时间 epoch 毫秒**;导出成"元"时必须用 `formatCents` 的整数算法,不得引入浮点。
- **净支出口径**:导出必须包含 `isRefund`,否则外部无法复算净支出。
- **前端只渲染,不算账**:CSV 的生成与解析都在服务端,前端只负责触发与下载。
- **导出端点必须在 `authModule.extraRoutes` 内**,否则无鉴权。
- **恢复是危险操作**,既有 CLI 已强制"停服才能恢复";UI 不得绕过这条护栏。
- 项目不引依赖:CSV 编码/解析自己写,放 `packages/shared`(纯函数,可单测)。

## Requirements

### R1 CSV 导出

- 至少导出**账单**;字段需包含:`日期`、`类型(收入/支出)`、`金额`、`分类`、`账户`、`备注`、`标签`、**`是否退款`**,以及一个稳定的 `id`
- 金额以**元**表示(两位小数),便于 Excel 直接计算;`是否退款`必须存在,否则外部无法按净支出复算
- **中文不得乱码**:需在 design.md 定夺并实测(倾向 UTF-8 + BOM,因为 Excel 在 Windows 上默认按本地代码页解析无 BOM 的 UTF-8)
- 字段中的逗号、引号、换行必须被正确转义(RFC 4180 风格),否则一条含逗号的备注就会毁掉整个文件的列对齐
- 也导出**工资记录**与**周期规则**,因为它们是账本的一部分
- 一次性导出全部相关表为一个可下载的文件,或每张表一个文件——design.md 定夺并说明

### R2 CSV 导入

- 必须能导入**由本应用导出的**账单文件
- 需要**幂等/去重策略**:同一份文件导入两次不得产生重复账单。策略在 design.md 定夺并说明依据(倾向使用导出时携带的 `id`)
- 必须处理**失败**:
  - 文件不是 CSV / 缺列 / 金额非法 → 明确报错,不得静默跳过
  - 分类或账户在本库不存在 → 必须明确报错或按明确规则处理,**不得静默丢弃该行**
  - 部分行失败时:全成或全不成,或返回逐行结果——design.md 定夺
- 导入结果必须返回**可读的统计**:新增多少、跳过多少(重复)、失败多少及原因
- 导入不得破坏既有数据:只新增,不修改/删除已有账单

### R3 备份管理界面

- 能看到**已有备份列表**(文件名、大小、时间)
- 能**手动触发一次备份**
- 能给出**恢复指引**。**是否允许在 UI 内执行恢复,倾向不做**——既有 CLI 已强制"停服才能恢复",UI 无法停掉自己所在的进程;design.md 必须给出结论与理由
- 备份目录与保留期沿用既有 `createBackup` 的语义,不新造一套

### R4 界面入口

- 从「我的」进入(与回收站、周期账单同级);不新增底部导航 tab(D12 已定 6 项)
- 导出:一键下载,完成后给出反馈
- 导入:选择文件 → 显示将发生什么 → 确认 → 显示结果统计
- 备份列表在无备份时显示空状态

### R5 移动端与无障碍

- 所有可点击元素 ≥ 44px;文件选择控件同样受此约束;375px 下无横向溢出
- 只用既有 CSS 语义变量

### 实现时发现的陷阱(值得记录)

**BOM 必须查字节,不能查字符串。** 我最初的 e2e 断言写成 `Buffer.from(await res.text(), 'utf8')` 后检查前三个字节,得到 `69 64 2c`(`id,`)——看起来像"服务端没写 BOM"。实际原因是 **`fetch().text()` 按编码规范会剥掉开头的 U+FEFF**,所以再编码回去时它已经不存在了。

用 `arrayBuffer()` 直查后确认服务端**是正确的**:原始字节为 `ef bb bf 69 64 2c 64 61`。已写进 `spec/backend/index.md`,避免下一个人重踩。

另一处是**我的测试用错了接口**:清空台账时调了 `DELETE /trash/:id`,而那是"彻底删除**已软删除**项",对正常账单返回 409(这正是 T12 的护栏在起作用)。改为"先 `DELETE /transactions/:id` 软删、再 purges"。

## Out of Scope

- **导入 Flutter 参考项目的存量数据** — 父任务 D8 明确不迁移;本任务只处理**本项目自己导出的**文件

- **在 UI 内执行恢复** — 见 R3
- **自动定时备份** — 与 1核1G 约束及"无常驻任务"的项目取向冲突
- **云端备份 / 对象存储上传**

## Technical Notes

- **CSV 编解码放 `packages/shared`**,纯函数 + 单测。理由与预算引擎、周期日期推算相同:规则应可独立测试,不应藏在路由里。
- **BOM 与 Excel**:`spec` 需记录实测结论(哪种编码下 Excel 中文不乱码),否则下一个人会重新试一遍。
- **去重键的选择**:导出携带的 `id` 是最可靠的键;若用"日期+金额+备注"做键,用户合法的重复消费会被误判为重复而丢失。design.md 必须论证这一点。
- **导入的日期解析**:导出用 `YYYY-MM-DD`(人类可读),导入必须按**本地日**解析,复用 `utils/money.ts` 的 `fromDateInputValue` 口径,不得用 `new Date(string)`(那是 UTC,会整体偏移一天)。
- **备份界面读目录**:需要一个列出 `DATA_DIR/backups` 的端点;注意不要返回宿主绝对路径给客户端(信息泄漏),只返回文件名与元数据。
- 新增 e2e 套件名为 `e2e-portability.mjs`。
