# 记账 Web PWA(信封预算 · 自建 VPS 部署)

> 父任务。拥有源需求集、子任务映射、跨子任务验收标准与最终集成评审。
> 本任务本身不含实现工作;实现由子任务承担(见 §子任务映射)。

## Goal

把参考实现 `E:\.01study\Projects\flutterProjects\keepingaccounts`(Flutter 手机端 + Spring Boot 后端)的核心记账能力,重建为一个**移动优先的 Web PWA**,部署到用户自己的 VPS + 域名上,让用户在 iPhone Safari 里"添加到主屏幕"后像原生 App 一样记账。

核心用户价值:在 iPhone 上随时记录收支,并由**信封预算法**自动回答"这个月我的各类预算还能花多少"。

## Background

参考项目 `keepingaccounts` 已实现并归档了 50+ 个 Trellis 任务,是一套成熟的业务规则来源。本次为**重建**,不是改造:

- 参考项目前端 = Flutter 3.x + drift(SQLite) + Riverpod + fl_chart
- 参考项目后端 = Spring Boot 3 + JWT + MySQL,同步用泛型 `sync_records` 表 + 客户端 UUID 幂等 + LWW 冲突解决
- 参考项目 78 个 Dart 源文件,已覆盖:预算、账单、模板、账户、分类、标签、退款、周期账单、统计、日历、深色模式、应用锁、通知、回收站、批量操作、多账户

需要重建的**核心业务不变量**(来自源码,非猜测):

1. **金额一律以"分"存整数**(`amountCents`),避免浮点误差 — `lib/data/models/transaction.dart:11`
2. **信封预算法全部实时计算,不物化余额** — `lib/data/repository/budget_engine.dart:22`
   - 模块可用额度 = 分配额 − 已消费;超支从"累积结余池"借用
   - 周期结束时模块剩余自动累积进结余池;结余池不因新周期开始而清零
   - 无现役周期时,消费直接从结余池扣减
3. **净支出口径** — `lib/data/repository/budget_engine.dart` §21 / `transaction.dart:46`
   - 退款是横切标记 `isRefund`,不是收入:type 仍是 0=支出
   - `expenseContribution` = 支出 `+amount` / 退款 `−amount`;`incomeContribution` = 收入 `+amount` / 退款 `0`
   - 所有聚合点(预算、图表、月汇总、首页)统一使用这两个 getter,不各处重复判断
4. **周期定义双模式** — `budget_engine.dart:32-91`
   - 默认:自然月为一个预算周期,同月多次记工资合并为同一周期(模块预算相加)
   - 可配置周期起始日(`cycleStartDay`,1..28,短月 clamp 到月末):如 15 号到次月 14 号
5. **软删除** — 所有业务表带 `deleted` 布尔列,不做物理删除(参考项目后期才补了物理删除任务)
6. **标签"名字即身份"** — 存标签名 JSON 数组,跨设备同名标签天然合并 — `lib/data/db/app_database.dart:97`

## Requirements

### R1 认证与会话(R1 由 D7 = 单用户决定)

- 单账号登录:用户名 + 密码
- 后端以 Argon2id(或等效)哈希存储密码;签发会话凭证供 PWA 长期持有
- 未认证请求一律 401;前端拦截 401 并跳登录页
- 必须支持"修改密码"
- 不实现:注册、找回密码邮件、多租户、第三方登录

### R2 账单记账(核心写入路径)

- 新增/编辑/删除:类型(收入/支出)、金额、分类、账户、日期、备注、标签
- 金额以分存储;前端输入"元"并在提交前转换为分
- 标签:多标签、名字即身份、去重保序
- 退款标记:支出行可标记为退款,参与净支出口径
- 账单列表:按月分组、倒序、支持筛选(类型 / 分类 / 账户 / 标签 / 日期区间 / 关键词)
- 删除为软删除

### R3 信封预算(产品的差异化核心)

- 分配模板:模块 = 分类 + 比例;预置一套默认模板,可增删改
- 独立"记工资"入口:输入工资金额后按模板比例自动生成各模块预算,**可逐项微调**
- 预算页:各模块进度条(已用 / 剩余)、超支高亮
- 累积结余池:历史周期剩余累积;当前周期超支从池借用;无现役周期时消费从池扣减
- 周期模式:自然月(默认)与可配置起始日(1..28)两种
- 全部实时计算,不物化余额

### R4 基础数据管理

- 分类:预置 + 自定义,含图标与颜色,区分收入/支出
- 账户:现金/储蓄卡/信用卡/支付宝/微信/其他,含初始余额
- 首次使用时播种预置分类、默认账户、默认模板

### R5 统计

- 近 30 天分类占比(饼图)
- 月度收支趋势(柱状图)
- 口径统一走净支出(`expenseContribution` / `incomeContribution`)

### R6 PWA 与移动端体验

- iPhone Safari 可"添加到主屏幕",独立窗口启动,有 App 图标与启动图
- Service Worker 缓存应用外壳:**断网可打开并查看已加载的数据**
- 写入类操作在离线时明确提示需要联网(不做离线写入队列,由 D4 决定)
- 移动优先布局:底部导航、44px 以上触摸目标、安全区(刘海/home indicator)适配

### R7 部署与运维

- 单一 `docker compose up -d` 拉起;与现有反代共存(应用监听内网端口)
- 数据持久化到宿主机卷;容器重建不丢数据
- HTTPS 由现有 Nginx/Caddy 终止
- 数据库文件备份方案(定时复制出容器)
- 环境变量管理密钥,不入库

## Acceptance Criteria(父任务级 · 跨子任务)

- [ ] AC1 在 iPhone Safari 打开域名,"添加到主屏幕"后是独立 App 观感(有图标、无浏览器地址栏)
- [ ] AC2 登录后可完整走通:记一笔支出 → 在预算页看到对应模块已用额增加、剩余减少

- [ ] AC4 模块超支时,超出部分从累积结余池扣减;下一周期开始时结余池保留
- [ ] AC5 标记为退款的支出行使净支出减少(而非计入收入)

- [ ] AC7 断网状态下打开 PWA 仍可查看账单列表与预算页
- [ ] AC8 `docker compose up -d` 在 2G 内存 VPS 上拉起成功,与现有反代共存不冲突
- [ ] AC9 容器删除重建后数据仍在(卷持久化验证)
- [ ] AC10 预算引擎的周期分组与结余池计算有单元测试覆盖,且测试在 CI/本地可重复运行
