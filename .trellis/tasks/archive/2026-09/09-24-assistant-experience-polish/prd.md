# AI 助理历史记录与首页入口体验优化

## Goal

让用户能清楚找回已保存的 AI 对话、看懂 AI 准备执行的记账内容，并从首页直接进入 AI 助理。

## Confirmed repository facts

- 助理对话和消息已经由 migration 009 持久化到服务端 SQLite；现有 API 能列出未归档对话并读取消息。
- 助理页只在对话数大于 1 时显示切换入口；确认卡目前直接显示内部字段名，例如 `amountCents` 和 `categoryId`。
- 底部导航有六个入口，保持数量及顺序能避免破坏已验证的窄屏导航。
- 首页已加载 `AppIcon` 并持有路由器，可通过现有导航直接打开 `/assistant`。

## Requirements

### R1. 可发现的对话历史

- 助理页始终展示清晰的历史记录入口和当前会话状态，而不是只有多条会话时才出现切换按钮。
- 历史项使用会话标题和最近更新时间；选择后恢复服务端保存的完整消息与卡片状态。
- 刷新或离开页面后重新进入时，默认恢复最近更新的未归档对话。
- 新建对话与归档当前对话继续通过已有服务端 API 完成；不得把对话内容只存在浏览器内存。

### R2. 易读的写入确认卡

- 账单确认卡用用户可理解的中文字段名呈现类型、金额、分类、账户、日期、备注和标签。
- 金额使用货币格式；分类/账户优先显示名称；空备注、空标签不展示原始 JSON。
- 突出显示操作名称、待确认/已完成状态、影响数量及警告；写入仍需用户显式确认。
- 微信/支付宝导入的行预览、选择、改分类、附件校验与二次确认行为保持不变。

### R3. 首页助理入口

- 首页上方提供醒目的 AI 助理入口，点击直达现有 `/assistant` 页面。
- 不增加底部导航项，不改变默认首页或现有手动记账入口。

## Acceptance Criteria

- [x] 历史入口在仅有一条对话时也可见；可在多条已保存对话间切换。
- [x] 页面刷新后可恢复最近对话；恢复内容来自现有 API，不依赖本地临时状态。
- [x] 账单卡显示中文字段名与格式化金额/日期/分类/账户，不出现 `amountCents`、`categoryId` 等原始键名。
- [x] 卡片在 375px 手机视口无横向溢出，确认与取消触控目标符合 44px 规则。
- [x] 首页助理入口可达；底部仍为六个导航项，手动记账仍可用。
- [x] 服务端类型检查、lint、测试，前端类型检查、lint、构建及助理浏览器用例通过；CSS 保持在既有 PWA 预算内。

## Out of scope

- 不新增迁移或改动会话 API、AI provider、账务服务与确认安全逻辑。
- 不改变归档语义、默认首页、底部导航、统计口径或 AI 提示词。
- 不添加会话搜索、重命名、导出或服务端存储配置。
