# Frozen implementation contract v1

User approved final MVP with 开始. This is normative for both tracks; protocol-draft is historical rationale. No production changes authorized.

## Routes / requests
Prefix `/api/v1/assistant/conversations/:conversationId`.
- POST `/generations`: `{version:1,clientRequestId:string,input:GenerationInput}`. 202 first,200 same canonical payload replay; strict unknown fields/IDs/text limits. clientRequestId1..120 (never truncate), trimmed text1..2000. GenerationInput `{type:'text',text}` | `{type:'choice',sourceGenerationId,questionId,optionId}` | `{type:'choice-text',sourceGenerationId,questionId,text}`. Never trust client label/tool/action arguments. Same request differing payload409 ASSISTANT_REQUEST_CONFLICT; active generation409 ASSISTANT_GENERATION_ACTIVE; bad/stale choice409 ASSISTANT_CHOICE_STALE. Normal auth/CSRF applies.
- GET `/generations?limit=1`: `{items:GenerationSnapshot[]}` most recent0/1.
- GET `/generations/:generationId`: `{generation:GenerationSnapshot}`.
- GET `/generations/:generationId/events?afterSeq=N`: SSE. afterSeq nonnegative safe integer, cannot exceed lastSeq; no model invocation. Missing replay ->409 ASSISTANT_REPLAY_UNAVAILABLE before headers; get snapshot not new POST. Unknown version/input ->400 ASSISTANT_GENERATION_INVALID.
- POST `/generations/:generationId/cancel`: no body, `{generation:GenerationSnapshot}` idempotent. Cancel cannot undo completed results or financial confirmations.
- Create returns `{created:boolean,generation:GenerationSnapshot}`.

## Snapshot (camelCase)
`{version:1,id:string,conversationId:string,userMessageId:string,userMessage:AssistantMessageDto,status,delivery,lastSeq,createdAt,updatedAt,partialMessages:Partial[],messageIds:string[],messages:AssistantMessageDto[],outcome:null|Outcome,error:null|{code,message}}`.
Partial `{messageId:string,step:number,text:string,validated:boolean}`. messages are validated assistant/tool DTOs produced by this generation (not full conversation; no progress persistence required for new flow). userMessage is accepted server-normalized user input and never fabricated client-side for choice. All IDs opaque server strings. Status accepted|running|completed|failed|cancelled|interrupted. Outcome answer|awaiting-choice|pending-confirmation. delivery stream|buffered.
Only completed status may carry outcome. completed NEVER means ledger booked. partial text provisional until matching message event. For terminal reconnect, snapshot authoritative even if replay absent. Latest/history read does not start model work.

## Events
UTF8 SSE, `id:<seq>`, `event:<type>`, one JSON data envelope `{version:1,generationId:string,seq:number,type,...}`. Per-generation seq positive contiguous; persist before publish. Four event types:
- state: `{status:'accepted'|'running'}`
- text-delta: `{messageId,step,offset,text}` UTF16 offsets; decoded complete Unicode characters, no split surrogate pairs; offset equals accumulated length, step0..2.
- message: `{message:AssistantMessageDto}` replaces partial same stable message ID. May include validated tool-card/text/result.
- terminal: `{status:'completed'|'failed'|'cancelled'|'interrupted',outcome:Outcome|null,messageIds:string[],error:null|{code,message}}`.
Heartbeat SSE comments, no seq/persistence. Duplicate seq ignored; gaps/offset mismatch reconcile snapshot, never concatenate blindly. Client interrupted connection != server failed; explicit status query/reconnect same generation, never automatic new POST/model retry.

## Clarification
Provider turn extends existing `{message,toolCall}` with optional `clarification:null|{question:string,options:string[]}`; cannot coexist with nonnull toolCall. question1..200; option labels1..100,2..6 unique nonblank. Server assigns public IDs and stores canonical answers. Validated text message content adds `{generationId,clarification:{id:string,selection:'single',question,options:[{id,label}],allowFreeText:true}}`. History remains existing message kinds. New input supersedes old question, answered/archived source stale; validate latest live unanswered source in transaction. Identical request replay checked before stale check. Click atomically consumes choice, appends normalized user answer and creates next generation. No financial confirmation. For user ordinary text while awaiting choice, supersede and proceed normally. History old options may appear but reject/disable stale via latest generation and lifecycle; authoritative server rejects regardless of UI.

## Runtime/persistence
Two additive tables assistant_generations/events, numbered migration011 if still next. Unique(conversation,request), active-generation partial unique index. Safe bounded partial/final/event JSON; schema normalization includes clarification/generationId. New and legacy message/analyse/archival entry points share active-turn exclusion. No hidden parallel legacy turn. Archive fences/cancels active generation; no late card or choice persistence. Producer continues when subscription lost within deadlines; Stop explicitly cancels and aborts reader. Server/app startup recovers accepted/running as interrupted without rerun; shutdown aborts all and cleans subscribers/timers. No external queue.
Final message/pending-action + completed status/terminal event transaction atomic; after every await check live generation/conversation before tools/finalize. Read tools may call nested providers but no financial writes before existing human confirmation. Deadline bounded across max3 steps, capped at180s and each provider at configured timeout; do not mutate saved timeout/model/secret. Unfinished outputs not authoritative model context. Migration old-client JSON history compatibility required.
No replay pruning in MVP: each generation hard-bounded to2048 events and <=2MiB serialized replay total (fail explicitly at bound), total display chars<=12000 across3 turns, <=4000 per turn. No per-token sync writes: batch complete characters at chunk boundaries with reasonable coalescing; never fake typing. A later retention policy requires review, do not delete user history now. Subscribers queue<=128 events/256KiB, close slow subscriber but producer persists. Heartbeat15s; enforce socket backpressure and cleanup.

## Provider
Chat-compatible stream true with delta.content only. Incremental UTF8/SSE bounded line64KiB/event128KiB/total2MiB, proper CRLF/comments/multiline framing, strict finish_reason stop + [DONE], no raw reasoning/tool args. Use bounded JSON tokenizer top-level unique message string, handle escapes/surrogates/nesting/duplicate keys/depth<=32; incomplete final envelope fails with no card. Provider envelope max2MiB and message max4000; only safe decoded text visible until full-envelope validation. Require server stream status/content type. No redirect credential forwarding. Saved response path must be supported Chat extraction (choices[0].message.content); other custom path explicitly buffered rather than silently interpret arbitrary paths. Chat stream failure never auto-fallback/retry. Responses/custom delivery buffered and labeled 完整回复模式, output appears once no simulated typing. Existing full endpoints compatible. Keep timeout active across body reading, cleanup controller/readers/timers on every completion/error/cancel.
Capture server today once generation, include explicitly in assistant prompt for each step and fixed-clock test, not device time.
