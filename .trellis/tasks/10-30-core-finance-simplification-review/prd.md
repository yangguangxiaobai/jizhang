# 核心记账与财务规划精简实施审查

## Goal

对照 `docs/superpowers/plans/2026-10-29-core-finance-simplification.md`，检查当前工作区的核心记账与财务规划改动是否满足预期，给出有源码和新验证结果支撑的偏差清单。

## Background

- 用户于 2026-10-30 要求检查现有实现，并明确同意创建审查任务。
- 起始分支为 main，HEAD 为 bde9a18，工作区已有 329 项未提交改动；包含大量与本计划相关的未跟踪文件。审查以当前文件为准。
- 需求基线为原总任务的 PRD、design 和 acceptance.md，以及 C1–C5 子任务合同。

## Requirements

- 覆盖 C1 核心入口与快捷记账、C2 工资与月计划、C3 统计与复盘、C4 手动存钱投资、C5 平台导入与按需 AI。
- 核对 G01–G06 的跨层金额、兼容、请求作用域和证据要求。
- 每个缺陷记录触发条件、实际与预期行为、优先级、源码位置和受影响验收 ID。
- 分开记录源码实现、本地自动化、设备验证和部署证据；原验收矩阵仍为未执行的情况需说明。
- 本次产出审查结果；后续产品修复、设备验收及部署须按各自授权和任务阶段推进。

## Acceptance Criteria

- [x] C1–C5 均有源码审查结果及对应验收 ID。
- [x] shared/server 的相关测试、lint、typecheck、build 和 Android JVM/lint/build 有本次命令结果，失败和环境限制均如实记录。
- [x] 报告中的缺陷已对照实际代码确认，重复或不成立的候选已移除。
- [x] review.md 说明符合预期的主要行为、影响使用的偏差、证据缺口和建议处理顺序。

## Scope Boundary

- 生产账本、部署和设备交互不作为本次自动化测试对象。
- 保留既有工作区改动；检查过程中生成的构建产物不充当产品验收证据。

## 追加需求：修复规划交接（2026-10-30）

用户在审查后要求“写一个规划文档我让其他模型来修复”。本任务继续交付规划，产品代码修复仍不在本轮范围。

- 目标：其他模型能够根据审查结果逐项修复，并独立验证是否达到原计划预期。
- 范围：覆盖 review.md 中 R01–R20；保留原 C/G 验收对应关系、兼容约束、未决请求安全处理及分级证据要求。
- 产物：[修复实施规划](../../../docs/superpowers/plans/2026-10-30-core-finance-simplification-repair.md)，以有顺序依赖和独立验收要求的任务组织。
- 验收：规划包含准确的修改/新增路径、接口、失败场景、步骤、命令及完成标准；所有审查编号可追溯；不得把文档交付记为业务修复完成。
- 范围外：本轮不修改产品代码、不预建一批修复任务、不启动 implementation、不执行生产操作。
- 阻塞问题：无。需求沿用已批准原设计；技术拆分和安全恢复方案作为交接建议明确写入文档。
