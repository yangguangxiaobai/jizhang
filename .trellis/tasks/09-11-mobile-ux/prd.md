# 移动体验增强 — 需求

> 父任务:`09-11-roadmap-2`,对应 R13。第二阶段「块五」。**必须最后做**:它要给全部新增视图统一加深色模式,先做会返工。

## Goal

两件让应用"能长期用下去"的事:

1. **深色模式** — 跟随系统 + 手动切换。晚上记账不该被一块白屏闪到。
2. **应用锁(PIN)** — 冷启动与超时后需要重新进入。记账应用打开就是全部财务数据,把手机递给别人时不该被看见。

## Background

### 参考项目行为(权威来源)

`lib/features/app_lock/`(6 个文件)与 `lib/core/app_theme.dart` + `theme_prefs.dart`:

- 应用锁:PIN 码设置、锁定页、忘记 PIN、PIN 输入组件、设置页
- 主题:深浅色主题定义 + 偏好持久化

**参考项目是本地 Flutter 应用,它的应用锁是真正的安全边界**(数据在本地、代码不可读)。**本项目是 Web,这条前提不成立**,必须明确写清(见 R2 与 design.md)。

### 必须遵守的既有硬约定

- **只用既有 CSS 语义变量**,不写死颜色。
- **所有可点击元素 ≥ 44px;输入 ≥ 16px 字号**(PIN 键盘尤其容易违反)。
- **不能只靠颜色传达状态**。
- 不新增底部导航 tab(D12 已定 6 项)。
- 全局偏好(主题、锁)适合 `localStorage` + 组合式函数,不需要进 Pinia store:单页读、单页写的偏好不值得进 store。

## Requirements

### R1 深色模式

- **跟随系统**为默认:`prefers-color-scheme: dark` 时不加任何操作就是深色
- 支持**手动切换**:`跟随系统` / `浅色` / `深色` **三态**,而非两态开关——两态开关会让"我想跟随系统"变成无法表达的状态
- 偏好必须**持久化**,刷新后保持
- 所有视图(含图表、进度条、结余池负数态、回收站、周期账单、待确认、数据页)**在深色下可读**,不得出现白底黑字或低对比度
- 图表是手写 SVG,用 CSS 变量描边/填充,应随主题自动变化——需**实测**确认
- 分类颜色来自数据库(ARGB 整数),是既有例外;深色下需保证可辨识
- **不得闪烁**:首屏渲染前就要定好主题(在 `index.html` 内联一小段脚本读偏好并设置属性),否则浅色会先闪一下

### R2 应用锁(PIN)

- 可设置 / 修改 / 关闭 PIN
- **冷启动需解锁**;解锁状态只在本次页面会话内有效(刷新即需重新解锁)
- "忘记 PIN"必须有明确降级路径,且该路径**不需要明文 PIN**
- **必须在 UI 与文档中写明:Web 上的 PIN 不是安全边界。** 前端代码可读、数据在服务端、会话 cookie 才是真正的凭证;PIN 的作用是"别人拿起你已解锁的手机时不直接看到账目",**不是**"防止有人拿到数据"。不得宣传为加密保护
- 锁定页不得泄漏任何财务数据(不显示用户名、金额、分类)

### R3 两者都不得破坏既有约束

- 深色模式与锁定页都必须通过既有的移动端审计(44px / 16px)与 PWA 审计
- 不新增底部导航 tab
- 不得回退第一阶段的任何验收项

### 实现时发现的真实缺陷(都被浏览器实测抓到,静态审计看不见)

1. **`--fg` 与 `--ok` 被全仓使用却从未定义**(定义的是 `--text`)。未定义的自定义属性会让整条声明在计算值阶段失效,于是这些颜色**静默回退**——浅色下"看着差不多"所以一直没被发现,深色下就不对了。已补齐两个令牌。
2. **25 处 `color: #fff` 压在 accent 上,深色下对比度仅 2.54:1**(低于 3:1)。深色 accent 是浅蓝,而按钮文字写死了白色。新增 `--on-accent` 令牌并全局替换。**这条只有实测对比度才能发现。**
3. **`SettingsView` 的周期选择器既无样式也无 44px**:`.cycle-row` 只在模板里被引用、没有任何 CSS 规则,浏览器回退到默认约 19px。**静态 CSS 审计对"根本没有规则"的控件是盲的**,已给审计补上这条检查。
4. **锁屏输错 PIN 完全没有提示**:`submit()` 先设 `error.value`、紧接着清空输入框,而 `watch(pin)` 把这个自身触发的变更也当成"用户开始纠正"并清掉了错误。用户第二次输入前看不到任何反馈。
5. **解锁标志放 `sessionStorage` 是错的**:按 Storage 规范它在刷新后依然存在,所以"刷新即上锁"从未生效。已改为**内存状态**,并把"加载应用即需解锁"作为 Web 上对"冷启动"的诚实定义写进 design.md —— 参考项目用的是超时重锁,Web 没有可信的 resume 信号。

## Out of Scope

- **生物识别(Face ID / Touch ID)** — Web 平台无可靠实现
- **服务端强制锁定 / 重新认证** — PIN 是本地界面门,不是访问控制;会话仍由 cookie 与 401 保护(见 R2)
- **加密数据库 / 端到端加密** — 服务端持有明文账本,这是既有架构
- **按分类自定义深色主题色** — 参考项目也没有
- **跟随系统的高对比度 / 减少动效偏好**
- **多用户各自的主题与 PIN**(D7 单用户)
- **PIN 尝试次数限制与锁定** — Web 前端可被绕过,做次数限制是安全剧场;真正的边界在服务端登录

## Technical Notes

- **深色模式的实现是补变量值,不是改组件。** 既有组件已全部使用语义变量,所以核心工作是 `styles/main.css` 增加一套深色值 + 一个 `data-theme` 属性选择器,以及一个切换控件。若发现某组件写死了颜色,**那是一个既有缺陷**,应修掉,而不是为新主题打补丁。
- **主题属性要能覆盖系统偏好**,因此用 `[data-theme='dark']` / `[data-theme='light']` 显式属性,而不是只靠 `@media (prefers-color-scheme)`,`跟随系统`态才回落到媒体查询。
- **`localStorage` 在隐私模式下会抛异常**,既有代码已有 try/catch 先例,照做。
- **PIN 必须存哈希而非明文**,即使是本地:存明文没有任何好处,且与既有 `password_hash` 的做法不一致。用 `crypto.subtle.digest`(Web Crypto 内置,无依赖)。加盐,避免相同 PIN 产生相同哈希。
- **"忘记 PIN"的降级路径**:清除本地 PIN 并进入登录页(而非直接进入账本)。这样它不会变成一个绕过锁的后门——用户仍需通过服务端密码登录。
- **锁定状态的判定**:"冷启动"= 新的页面加载,因此用 `sessionStorage` 标记"本次会话已解锁"。刷新即需重新解锁,且不需要定时器。
- 本任务不改后端,因此没有新服务端套件;验证靠**浏览器实测**(新增 `render-theme.mjs`,复用 `lib/browser.mjs`)+ 构建期审计。
- 必须**实测深色下的对比度**:用浏览器算出关键文本与其背景的实际颜色并断言对比度比值,而不是靠肉眼。`render-*.mjs` 已具备 `evaluate` 能力。
