# Android AI 接口设置页 (ProviderSettings) 只读 UI/交互审计与重构方案

## 0. 背景与审计范围

- **目标页面**: 原生 Kotlin Jetpack Compose 实现的 `ProviderSettings`（位于 `clients/android/app/src/main/java/com/yansuu1/jizhang/ui/ProviderSettings.kt`），由 `MyTab.kt`（我的 -> AI 接口设置）与 `AssistantTab.kt`（助理右上角菜单/提示）路由接入。
- **任务性质**: 只读 UI 与交互可用性审计，制定可实施、无行为变更的重构方案。**不修改产品代码、不发起实际网络请求或付费推理调用、不创建或推进流程任务、不提交代码。**
- **工具与环境状态**: 本会话中 `ardot` MCP 服务连接状态为 `disconnected`。本方案严格基于 Nielsen Norman 移动端可用性原则（系统状态可见性、防错原则、识别优于回忆）、Android Material Design 3 规范与项目现有设计系统 Tokens（`LocalWebTokens`, `LocalMotionTokens`）开展。
- **契约完整保留**: 完整保留功能清单 A038–A062：
  1. 模型拉取 (`POST /api/v1/ai/models`)、客户端搜索过滤、手填任意模型、显式保存 (`PUT /api/v1/ai/config`) 语义；
  2. 密钥遮罩输入、留空保留服务器密钥、清除确认弹窗与待保存标记；
  3. 三种模式（`chat-completions`、`responses`、`custom`）；
  4. 三种认证（`bearer`、`header`、`none`）；
  5. 超时时间 (3,000–60,000 ms)、额外请求头 JSON 校验、请求体模板 `bodyTemplate`、响应路径 `responsePath`；
  6. 保存、测试、拉取模型全互斥锁定；
  7. 零自动付费推理、零明文密钥回显。

## 2. 推荐的信息架构与重构策略

根据主会话指导方向与 Nielsen Norman 原则，将原本割裂的 4 张卡片调整为 4 层递进式结构 + 常驻底部操作栏：

### 2.1 架构分层
1. **顶部真实状态摘要卡 (Card 1: 真实状态与开关)**:
   - **服务端真实状态 (Persisted)**: 基于 `savedDraft.enabled` 展示「服务端已启用 (绿)」或「服务端未启用 (灰)」，并展示加密密钥状态（`hasSecret`）；
   - **草稿变动感知 (Draft Dirty)**: 切换开关时仅标记草稿变动，显示「(草稿待保存)」，副标题明确标注「需点击底部保存配置后生效」，消除“一开即用”的虚假心理认知；
   - **真实连通性结果**: 仅在显式执行测试后展示（耗时 XX ms 或具体错误诊断）。
2. **连接基础设置卡 (Card 2: 连接、模式与认证就近配置)**:
   - 配置名称 (可选)
   - 服务地址 (Base URL)，支持 New API 根域名自动补全
   - 接口模式就近配置 (Chat Completions / Responses / 自定义) —— 模式直接决定了 URL 补全规则和请求语义，放在连接卡更合理
   - 认证方式就近配置 (Bearer / 自定义头 / 无认证) —— 紧随其后配置对应密码框与密钥安全清除/撤销操作
3. **独立模型卡片 (Card 3: 统一模型选择器与刷新入口)**:
   - **单一主选择入口**: 整合手填输入框与右侧下拉/选择弹窗触发按钮（显示当前已缓存模型数）；
   - **显式拉取按钮**: [刷新/拉取模型列表]（基于服务器已保存配置请求，互斥转圈）；
   - **常用模型平滑收纳**: 将 6 个常用模型标签（gpt-4o-mini、deepseek-chat 等）作为快速填入预设，移至模型选择弹窗/底部面板顶部，不在主卡片页面外露堆叠，彻底精简主屏，保留完整一键填入能力。
4. **高级协议与请求设置 (Card 4: 折叠收拢)**:
   - 折叠标题 + 摘要行（展示当前模式、认证、超时秒数）；
   - 展开内容：HTTP 方法、超时毫秒数、额外请求头 JSON、自定义请求体模板、响应路径；
   - 字段就近报错：校验失败时精准定位并标红，不再抛给全局。
5. **固定底部操作栏 (Fixed Bottom Bar / Scaffold BottomBar)**:
   - 独立常驻屏幕底端，脱离滚动列表；
   - 顶部提供草稿脏检查提示条（「⚠️ 有未保存修改，测试将针对已保存配置」）；
   - 双按钮并排：
     - `[测试连接]` (次要操作 / OutlinedButton): 有未保存草稿时禁用并提示；
     - `[保存配置]` (主要操作 / FilledButton): 主视觉强调，保存中显示 Loading。

## 5. 潜在风险与规避策略

1. **软键盘弹出挤压底部操作栏**:
   - *风险*: 在小屏设备上软键盘弹起时，固定的底部操作栏可能被顶起并遮挡正处于焦点下的文本输入框。
   - *规避*: 在外层容器使用 `Modifier.imePadding()`，并在焦点切换时借助 `bringIntoViewRequester` 或系统默认滚动机制自动平滑将输入框滚入视口。
2. **模式与认证前置可能引起高级用户混淆**:
   - *风险*: 将模式与认证从高级设置移到连接卡后，若用户选择「自定义」模式，仍需在高级卡片中填写自定义请求体与响应路径。
   - *规避*: 当用户在连接卡选择「自定义」模式时，以动态高亮或轻量文字提示「自定义模式需在下方高级设置中配置请求体模板与路径」，折叠摘要同步更新为「自定义模式 (需配置模板)」，引导顺畅。
3. **未保存状态下测试连接的提示冲突**:
   - *风险*: 用户修改了连接配置后急于点击测试，测试按钮禁用可能使用户疑惑。
   - *规避*: 在底部操作栏的提示条明确用琥珀色文案写出：「草稿已修改，测试仅针对服务端已保存配置，请先点击保存」，消除困惑。

## 6. 不改变行为的回归检查与设备验收标准

| 验收项 | 操作与断言 | 对应功能契约 |
|:---:|---|---|
| 1. 加载防空阻断 | 初始弱网或失败时禁止保存空配置，给重试按钮 | A038 |
| 2. 开关草稿语义 | 切换开关仅变更草稿，不篡改服务端，未保存离开服务端不变 | A039 |
| 3. 三种模式保留 | Chat / Responses / 自定义模式随意切换，不丢失模板和路径 | A040 |
| 4. 模型拉取互斥 | 拉取模型基于已保存配置，拉取中禁用其他操作，失败不覆盖模型名 | A041, A056 |
| 5. 密钥留空安全 | 密码框遮罩，留空保存不抹除密钥，清除需二次弹窗确认并可撤销 | A043, A045 |
| 6. 高级折叠与动效 | 折叠动画遵循 `LocalMotionTokens`，`reduced` 模式无过渡动画 | A046 |
| 7. 客户端校验拦截 | 超时范围 (3000-60000) 与 JSON 语法错误即时阻断保存并标红 | A048, A049, A052 |
| 8. 测试独立性 | 测试仅针对服务端已保存配置，未保存时禁止测试 | A054, A055 |
| 9. 零自动付费推理 | 整个设置页无隐式或后台对话调用，拉取模型不触发推理 | A060 |
| 10. 暗色主题适配 | 切换暗色主题，`ProviderNotice` 警告背景与文字无亮色刺眼硬编码 | 界面规范 |
