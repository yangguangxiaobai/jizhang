# Tag-foundation independent re-review

**Scope:** `.trellis/tasks/10-19-ai-spending-organization` backend tag-foundation slice, with the original independent review, the fix report, migration 013, catalog/master-data/transaction services and routes, and relevant database/master-data/transaction/AI-organization tests. This is not a review of the full AI organization feature.

**Verdict: CONDITIONALLY ACCEPTABLE FOR THE SEVEN REVIEW FINDINGS; one residual P2 parity issue remains.** Six reviewed behavior areas appear fixed and supported by source/tests; rollback is specifically exercised at migration 013 failure. The remaining issue is Unicode length semantics: SQLite SQL truncation counts Unicode code points, while the legacy TypeScript normalizer truncates UTF-16 code units. This can make a tag with astral characters resolve to different canonical values across SQL migration/filter and JS parsing paths.

## Seven findings rechecked

1. **Valid non-array JSON / malformed JSON — addressed.** Migration backfill gates `json_each` on both `json_valid` and `json_type='array'` (`packages/server/src/db/migrations/013-tag-hierarchy.ts:20-25`); both triggers have the array guard and safe fallback (`:39-45`, `:81-87`). The transaction membership SQL uses the same gate (`packages/server/src/services/transaction-service.ts:37-41`). Tests insert object, scalar and malformed values, verify they do not create catalog associations, and preserve the original JSON (`packages/server/test/db.test.ts:105-164`, `master-data.test.ts:637-650`).
2. **Rename/merge hierarchy orphaning — addressed.** Legacy merge rejects either source/target with active children, and rejects differing parent positions before the rewrite transaction (`packages/server/src/services/master-data-service.ts:535-543`). Regression tests check parent-to-existing-root and cross-branch rename conflict and unchanged metadata (`packages/server/test/master-data.test.ts:652-665`).
3. **Parent/child deduplicated counts — addressed.** Catalog list parses each live transaction through `parseTagsJson`, counts a root’s own/direct-child names once per transaction and child names exactly (`packages/server/src/services/tag-catalog-service.ts:24-42`). Regression fixture includes direct parent, child, both on the same bill and a deleted child bill; root count is asserted as 3 and filter total is also 3 (`packages/server/test/master-data.test.ts:600-620`).
4. **Blank `tagId` — addressed.** A provided empty or whitespace selector fails route parsing (`packages/server/src/routes/transactions.ts:41-47`); service direct calls independently reject blank and unknown/deleted IDs (`packages/server/src/services/transaction-service.ts:824-829`). Tests distinguish absent, blank, whitespace, unknown and valid (`packages/server/test/master-data.test.ts:622-635`).
5. **Canonical trim/cap/dedup and 20-association count — mostly addressed, Unicode residual below.** SQL paths trim before capping, deduplicate in first-seen order and cap unique names at 20 (migration `:17-37`, triggers `:48-78` and `:90-120`; filter SQL `packages/server/src/services/transaction-service.ts:31-45`). Tests cover leading/trailing ASCII whitespace, duplicate-before-boundary, 32-character caps, ignored 21st unique association, and byte-preservation (`packages/server/test/db.test.ts:105-164`). But SQL `substr(...,1,32)` and TypeScript `name.slice(0,32)` do not measure astral characters the same way; see residual.
6. **Migration 013 rollback — addressed and directly tested.** The test applies 001–012, creates a conflicting trigger so migration 013 fails after starting DDL, then asserts `tags`, its index, the update trigger, and version 13 are absent (`packages/server/test/db.test.ts:167-181`). This is migration-specific rollback evidence, not only a generic runner transaction test.
7. **Read-only GET / hierarchy lifecycle — addressed.** `/api/v1/tags/hierarchy` GET directly calls `listTagHierarchy()` and performs no write (`packages/server/src/routes/master-data.ts:116-118`; service list only selects). Test compares catalog count before/after GET, and also checks no third level and that a parent with children cannot be deleted (`packages/server/test/master-data.test.ts:668-680`).

## Cross-writer and undo check

Migration triggers are installed on transaction INSERT and `UPDATE OF tags_json`, so direct SQL writers are covered in the database transaction boundary; direct insert/update tests assert catalog synchronization and unchanged raw JSON (`packages/server/test/db.test.ts:136-164,183-189`). AI apply/undo uses those transaction updates and the AI organization test exercises a tag merge, verifies the tag JSON and active catalog state after apply and restored source JSON/catalog state after undo (`packages/server/test/ai-organization.test.ts:180-253`). `AiOrganizationService` also validates affected transaction state before undo (`packages/server/src/services/ai-organization-service.ts:951-962`); a direct intervening category write is tested as a 409 conflict (`ai-organization.test.ts:308-325`). The tests do not specifically simulate an intervening direct-SQL tag change before undo, so that distinct conflict route remains source-reviewed rather than directly regression-tested.

## Residual finding

### [P2] SQL and JS tag-length caps differ for astral Unicode

- **Exact locations:** `packages/server/src/services/tags.ts:31-34` (`name.slice(0, MAX_TAG_LENGTH)`), migration `packages/server/src/db/migrations/013-tag-hierarchy.ts:18` (also corresponding SQL expressions in triggers at `:49`, `:65`, `:91`, `:107`), and transaction SQL `packages/server/src/services/transaction-service.ts:35,42-43`.
- **Reason:** JavaScript string `.slice(0, 32)` counts UTF-16 code units. SQLite `substr(text,1,32)` counts Unicode characters/code points. A string made of 20 emoji followed by ASCII characters can be truncated at a different boundary. JS canonicalization may produce 16 emoji (32 UTF-16 units), while SQL can produce 20 emoji (32 code points). Therefore a legacy/direct-SQL transaction may be parsed by `parseTagsJson` into one association but migration/triggers/filter SQL treat a longer distinct value as its identity. The ASCII and BMP cases currently tested do not expose this.
- **Impact:** A narrowly scoped legacy-data identity/filter/catalog mismatch for names containing supplementary-plane characters at the 32-unit boundary. Ordinary service writes normalize through JS and remain consistent with JS semantics, but migration/direct writers and raw JSON reads can disagree.
- **Suggested resolution:** Either explicitly redefine the canonical limit in code/docs to count Unicode code points and update the JS normalizer accordingly (compatibility impact must be considered), or make SQL truncate according to the existing UTF-16 code-unit contract. Add migration, trigger, parser and filter regression cases using astral symbols at the boundary while confirming raw JSON is unchanged.
