# Design

Reuse deterministic platform account/day/type/amount matching in PortabilityService, exposing paginated current candidates with stable IDs and historical reference labels. Preserve legacy duplicateOfNote for compatibility; do not embed unbounded full ledger candidates or send them to AI. Provide authenticated read-only action/row-scoped endpoint resolving facts from stored bounded preview, validating conversation/action ownership and status, with strict bounded limit/cursor validation. Prefer existing transaction/detail projections rather than parallel financial logic. Responses contain total/paging and safe source/match rationale; dates use existing server-local semantics.

Android owns comparison overlay/subview state by action+row and request generation. Render vertical source versus existing comparison on small screens, full notes and candidate pagination. Keep parent workspace mounted with remembered list state. Explicit keep/include or exclude changes only selected source ID; enforce current eligibility/busy/100 cap and never auto-dismiss into confirmation. Read errors preserve parent drafts; close/system back returns to same list. Reuse existing detail presentation where practical, no edit controls.

No migration preferred. Additive preview/source fields covered by deterministic fingerprints; old pending actions missing facts get explicit refresh guidance, not inferred matches from arbitrary client amounts/account IDs. Candidate changes do not rerun model; final ledger confirmation remains unchanged. Test route auth/ownership/pagination/current deletion and frontend draft/request isolation; no deployment in implementation gate.
