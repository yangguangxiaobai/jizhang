# 记账 PWA 第二阶段:补齐日常功能与正式上线

> 父任务。拥有第二阶段源需求集、子任务映射、跨子任务验收标准与最终集成评审。
> 本任务本身不含实现工作;实现由子任务承担(见 §子任务映射)。

## Goal

第一阶段(父任务 `09-11-web-pwa`)交付了一个**可用的 MVP**:登录、账单 CRUD 与筛选、标签、退款、分类/账户管理、信封预算 + 结余池、工资录入与模板、统计图表、PWA 外壳、容器部署。

第二阶段的目标是把这个 MVP 变成**每天真的会用**的应用。判断标准很直接:第一阶段的验收全部通过,但存在若干"数据在库里、入口不存在"的缺口,以及参考项目已实现、本项目明确推迟的日常高频功能。补齐这些缺口后,应用才能替代参考的 Flutter 项目成为日常记账工具,并真正跑在用户的 iPhone 上。

### 待补齐的缺口(仓库证据,非猜测)

1. **软删除数据没有入口** — 账单删除是软删除(`deleted` 列),但前端没有任何入口列出、恢复或彻底删除已删除账单。参考项目有 `features/trash/trash_page.dart`(285 行,支持恢复/彻底删除/全部恢复/全部清空)。数据库里现在就可能存在只增不减的垃圾数据。
2. **首页缺失** — 参考项目的 `features/home/dashboard_page.dart`(497 行)是日常打开 App 的第一屏,承载本月概览 + **待确认到期账单**。本项目当前 `AppShell` 直接落到账单列表,没有概览屏。
3. **周期账单完全缺失** — 参考项目有完整模型 `data/models/recurring_transaction.dart`(5 种频率 `daily/weekly/monthly/quarterly/yearly`、`nextDueDate`、`hasOlderDue`、`enabled`)+ `recurring_rules_page.dart` + `due_notification_planner.dart`。房租、订阅这类账单现在必须每月手输。
4. **历史预算分配不可见** — `budget_allocations` 表**已经在按周期存历史**,但前端只能看当前周期。一个周期结束后,上月的模块预算与超支就再也看不到,结余池趋势也只有单条曲线。这是"数据在库里、入口不存在"的最典型缺口。
5. **没有数据出口** — 只有 `cli.js backup`(整库备份)。想用 Excel 分析、想核对账目、想换设备时,没有任何导出/导入能力。参考项目也没有,但这是 `Out of Scope` 里唯一"因为没人做"而非"因为不需要"的项。
6. **移动体验缺口** — 参考项目有深色模式(`app_theme.dart` + `theme_prefs.dart`)、应用锁 PIN + 忘记 PIN(`features/app_lock/` 6 文件)、本地到期通知(`features/notifications/` 6 文件)。本项目第一阶段的 `Out of Scope` 明确推迟了深色模式与应用锁。
7. **未上线** — `09-11-t10-production` 仍为 `in_progress`,父任务 AC1–AC9 尚未在真实 iPhone 上测量。这是唯一**用户无法自行验收**的一块。

## Requirements

### R8 首页仪表盘(块一)

- 作为打开应用的第一屏,展示**本月概览**:本月收入 / 本月支出(净支出口径)/ 本月结余
- 展示当前预算周期的**可用额度总览**,并可跳转到预算页
- 展示**最近账单**(少量条数),并可跳转到账单列表
- 在周期账单功能落地后,展示**待确认到期账单**入口
- 口径一律复用第一阶段的 `expenseContribution` / `incomeContribution`,不在前端重新发明计算
- 不改动底部导航的信息架构前提下,首页应有明确入口(允许调整导航,但需在 design.md 说明)

> **已决(D11,用户 2026-09-11)**:首页「本月收入」**计入工资记录**,且该口径在**所有页面统一**(首页与统计页一致)。这要求后端 `stats-service.monthlyTrend` 把 `salary_records` 计入收入,是第二阶段唯一的"修改第一阶段既有语义"的改动;统计页既有 e2e 断言需同步更新。工资**不计入** `categoryShare`(工资无分类,强行归类即编造数据)。
>
> 已知且接受的副作用:若用户既用「记工资」录入、又手工记一笔收入账单,同一笔钱会被计入两次。**决定不做去重**——两条记录在数据上确实是两条独立事实,任何自动去重规则都会误删合法数据。详见 `09-11-home-dashboard/design.md` §2.5。

### R9 回收站(块一)

- 列出所有已软删除的账单(按删除时间倒序),展示金额、分类、日期、原账单日期
- 单条**恢复**;单条**彻底删除**(物理删除,不可撤销,需二次确认)
- **全部恢复**;全部**彻底删除**(需二次确认,文案明确说明不可撤销)
- 恢复或彻底删除后,账单列表与预算页的聚合结果立即反映变化
- 面向账单之外的软删除实体(分类/账户等)在库中同样可软删除,但其**回收站 UI 本期可不做**,需在 design.md 明确界定

### R10 周期账单(块二)

- 周期规则:`名称`、类型(收入/支出)、金额、分类、账户、频率(`daily/weekly/monthly/quarterly/yearly`)、锚定日期、启用开关
- 参考项目的 `nextDueDate` 与 `hasOlderDue` 语义必须逐条复刻:**已到期**的规则要能生成账单,**过期未处理的**到期点不能静默丢失
- **待确认**机制:到期账单不静默入账,而是进入"待确认"状态由用户确认后落为真实账单(参考项目即此语义,避免自动记账污染账目)
- 规则可增删改、可启停;禁用规则不再产生待确认项
- 到期提醒:**先验证 iPhone PWA 上的可行性**。iOS 的 Web Push 需要"添加到主屏幕"且受系统限制,若不可行,降级为**应用内提醒**(打开应用时提示待确认数量),并把结论写入 spec
- 生成账单必须走第一阶段的净支出口径,退款标记语义不因来源不同而改变

### R11 预算深化(块三)

- **历史周期回看**:可切换到任意有分配记录的周期,查看该周期的模块预算、已用、剩余、超支
- **结余池趋势**:从第一阶段单条曲线扩展为可按周期观察的结余池变化
- **多模板**:**已在第一阶段(T6)完整交付,本任务只复核,不重做。** 证据:模板 CRUD 与设为默认 `routes/budget.ts:200-235`;比例校验(和必须为 1,容差 `1e-4`)`template-service.ts:81-114`;前端模板管理页 `TemplatesView.vue`;记工资时可选模板 `SalaryEntryView.vue:162-169` + `:126` 提交 `templateId`,服务端 `salary-service.ts:224-229,288-291` 按其生成分配;已被 `test/budget.test.ts:183-209` 与 `e2e-budget.mjs:177-189`(显式使用非默认模板)覆盖
- 历史周期的数据读取必须使用引擎的既有口径,**不得为回看另写一套计算**;若引擎缺少"给定周期计算模块视图"的能力,应扩展引擎并补单测,而不是在路由层拼算

> **范围更正(2026-09-11):** R11 原本有三条,核实后发现第 3 条已在第一阶段完成,故本块的**真实工作量约为两条**(历史回看 + 结余池趋势)。同时确认 **`poolTrend` 已存在**(`stats-service.ts:309-340`),因此"结余池趋势"可能只需前端呈现,后端无需改动。详细结论以 `09-11-budget-history/design.md` 为准。

### R12 数据安全与迁移(块四)

- **导出**:至少支持 CSV;目标格式需能直接用 Excel 打开且中文不乱码(需在 design.md 定夺字符集方案)
- **导入**:支持从第一阶段导出的 CSV 回灌,需定义幂等/去重策略与失败处理
- **备份管理界面**:可视化查看已有备份、手动触发备份、并给出恢复指引。**危险操作(恢复)是否允许在 UI 内执行需在 design.md 定夺**,倾向仅展示 + 命令行恢复
- 导出内容与口径需与预算/统计一致(净支出),导出字段需包含退款标记,否则导出数据无法外部复算

### R13 移动体验增强(块五)

- **深色模式**:跟随系统 + 手动切换,偏好需持久化;所有视图(含图表、进度条、结余池负数态)在深色下可读
- **应用锁**:PIN 码锁定,冷启动与超时后需解锁;支持"忘记 PIN"的明确降级路径。**在 Web 上 PIN 不是安全边界**(前端代码可读),必须在 design.md 写清此限制,不得把它宣传为加密保护
- 两者都必须通过第一阶段已有的移动端审计(44px 触摸目标)与 PWA 审计,不得回退

### R14 正式上线(块六)

- 复用已有 `09-11-t10-production` 任务,不新建重复任务
- VPS 上线、HTTPS、域名访问、iPhone "添加到主屏幕"
- 反代接入必须**纯增量修改**,改前备份,改后逐个复核既有站点仍正常
- 上线后逐条测量第一阶段父任务 AC1–AC9

## Technical Notes

- **阶段一的不变量在本阶段全部继续生效**:金额整数分、时间 epoch 毫秒、月分组键为整数 `year*100+month`、净支出走 `expenseContribution`/`incomeContribution`、`periodStartOf` 按目标月 clamp、软删除不物理删除(除非回收站的"彻底删除")。
- 前端**只负责渲染**,不做记账口径计算 — 这是第一阶段的硬约定,第二阶段新增页面必须遵守。
- 新增的后端能力必须补单测;新增的端到端流程必须补 `packages/server/scripts/e2e-*.mjs` 套件并接入既有重置基线(`scripts/lib/e2e-reset.mjs`)。
- 参考项目源码 `E:\.01study\Projects\flutterProjects\keepingaccounts` 仍是**业务语义的权威来源**。涉及周期账单、回收站、深色模式、应用锁的具体行为,先读源码再设计,不猜测。
- 每块交付都必须跑通既有的质量门:`pnpm lint`、`pnpm typecheck`、单测、前端构建期审计(移动端 + PWA)、容器 e2e。
- `.trellis/spec/` 需在每块结束时补充新约定(周期账单语义、导出格式、深色模式令牌),不留占位。

## 子任务映射

父任务不直接实现。子任务按下表创建,每个子任务独立可验收、可归档。

**顺序即依赖**:块一 → 块二 → 块三 → 块四 → 块五 → 块六。顺序理由是集成成本,不是技术依赖:

- 块一(首页 + 回收站)必须在块二之前,因为首页要承载周期账单的"待确认"入口,先做首页可避免首页返工
- 块二(周期账单)必须在块四(导出)之前,因为导出字段要覆盖周期账单生成的账单
- 块三(预算深化)与块一/块二无强依赖,可并行推进
- 块五(移动体验)放在功能之后,因为它需要给新增页面统一加深色模式与应用锁,先做会返工
- 块六(部署)放在最后,因为它需要把前面的构建产物一次性上线,避免多次上线

| 子任务 | 交付物 | 依赖 |
|---|---|---|
| T11 首页仪表盘 | 本月概览、周期额度总览、最近账单、待确认入口位 | 无 |
| T12 回收站 | 软删除账单的列出 / 恢复 / 彻底删除 / 批量操作 | 无 |
